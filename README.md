# رهنما سیستم شرق

سایت فروش نمایندگی رسمی سپیدار سیستم — مشهد، شهرک صنعتی توس.

## اجرای محلی

```bash
npm install
cp .env.example .env.local
```

سپس یک پستگرس محلی بالا بیاورید (داکر):

```bash
docker run -d --name rahnama-pg -e POSTGRES_USER=rahnama -e POSTGRES_PASSWORD=rahnama -e POSTGRES_DB=rahnama -p 5433:5432 postgres:16-alpine
```

ساختار دیتابیس و کاربر پنل:

```bash
npm run db:migrate
npm run db:create-admin -- admin "یک-رمز-قوی" "نام شما"
```

و بالاخره:

```bash
npm run dev
```

سایت روی `http://localhost:3000` و پنل روی `/admin/login`.

| دستور | کار |
| --- | --- |
| `npm run dev` | سرور توسعه |
| `npm run build` | ساخت نسخه production |
| `npm start` | اجرای نسخه ساخته‌شده |
| `npm run lint` | بررسی کد |
| `npm run typecheck` | بررسی تایپ‌ها |
| `npm run db:migrate` | ساخت/به‌روزرسانی جداول دیتابیس |
| `npm run db:create-admin` | ساخت کاربر پنل (یا تغییر رمزش) |

## قواعد پروژه

**۱. افزودن محصول جدید = ویرایش یک فایل.**
یک شیء به آرایه‌ی `products` در `lib/products.ts` اضافه کنید. صفحه‌ی محصول، منو،
فوتر و `sitemap.xml` خودکار به‌روز می‌شوند.

**۲. تغییر آدرس یا تلفن = ویرایش `lib/site.ts`.**
همان مقدار در هدر، فوتر، صفحه تماس و `LocalBusiness` schema استفاده می‌شود.

**۳. هر صفحه دقیقاً یک `<h1>` دارد.**
عنوان اصلی صفحه با `<SectionHeading as="h1" />` نوشته می‌شود، بقیه سرتیترها `h2`.

**۴. راست‌چین با ویژگی‌های منطقی.**
به‌جای `left/right` از `start/end` استفاده کنید (`ps-4`, `me-2`, `start-0`).
`dir="rtl"` روی `<html>` است و این کلاس‌ها خودکار برعکس می‌شوند.

**۵. عدد فارسی برای محتوا، لاتین برای تماس.**
قیمت و آمار با `formatPrice()` / `formatNumber()`. شماره تلفن و ایمیل با
کلاس `ltr` تا در متن فارسی به‌هم نریزد.

**۶. هیچ درخواست خارجی.**
فونت وزیرمتن در زمان build دانلود و کنار سایت میزبانی می‌شود. تصاویر با
`next/image`. هیچ CDN خارجی اضافه نکنید — هم کند است هم برای کاربر ایرانی
غیرقابل‌اتکا.

## محیط‌ها

| محیط | شاخه گیت | ایندکس گوگل |
| --- | --- | --- |
| توسعه (محلی) | `dev` | ❌ `NEXT_PUBLIC_ALLOW_INDEXING=false` |
| production | `master` | ✅ `NEXT_PUBLIC_ALLOW_INDEXING=true` |

`robots.ts` تا وقتی `NEXT_PUBLIC_ALLOW_INDEXING=true` نباشد کل سایت را
`Disallow: /` می‌کند. این جلوی ایندکس‌شدن نسخه آزمایشی را می‌گیرد.

## قواعد فاز ۱

**قیمت هرگز از فرم خوانده نمی‌شود.**
در `app/(site)/checkout/actions.ts` مبلغ همیشه سمت سرور از دیتابیس خوانده می‌شود.
اگر از فرم می‌آمد، کاربر می‌توانست در ابزار توسعه‌دهنده مرورگر عوضش کند.

**تومان در سایت، ریال در درگاه.**
همه‌جای سایت تومان است. تبدیل به ریال (×۱۰) فقط در `lib/payments/zarinpal.ts`
و `lib/schema.ts` انجام می‌شود. جای دیگری تکرارش نکنید.

**کلید «خرید آنلاین» فقط وقتی روشن شود که درگاه واقعاً کار کند.**
صفحه محصول کش می‌شود و وضعیت درگاه را نمی‌خواند؛ فقط این کلید را می‌بیند.
صفحه تسویه به‌عنوان تور ایمنی نبودِ درگاه را مدیریت می‌کند.

**افزودن درگاه سوم = یک فایل جدید در `lib/payments/`.**
واسط `PaymentProvider` را پیاده کنید و در `index.ts` ثبتش کنید. صفحه تسویه
و جریان سفارش دست نمی‌خورند.

## قواعد فاز ۲

**سرنخ هرگز به‌خاطر ایمیل از دست نمی‌رود.**
`app/(site)/consultation/actions.ts` اول در دیتابیس ذخیره می‌کند، بعد ایمیل
می‌فرستد. اگر SMTP خراب باشد فرم همچنان موفق است و ستون `notified` نشان
می‌دهد کدام اعلان‌ها نرفته‌اند.

**ساعت کاری به وقت تهران است، نه وقت سرور.**
سرور لیارا احتمالاً UTC است. `lib/availability.ts` تبدیل را با اختلاف ثابت
+۰۳:۳۰ انجام می‌دهد (ایران از ۱۴۰۱ ساعت تابستانی ندارد). اگر این تبدیل
نبود، رزرو ساعت ۱۰ صبح در پنل ۶:۳۰ صبح دیده می‌شد.

**زمان انتخابی سمت سرور دوباره اعتبارسنجی می‌شود.**
مقدار فرم قابل دستکاری است. `isValidSlot()` جمعه، ساعات غیرکاری، زمان‌های
گذشته و زمان‌های وسط بازه را رد می‌کند.

**دو رزرو همزمان با ایندکس یکتای دیتابیس گرفته می‌شود.**
`leads_slot_unique` یک ایندکس جزئی است؛ اگر دو نفر هم‌زمان یک بازه را
بفرستند، دومی خطای ۲۳۵۰۵ می‌گیرد و پیام فارسی می‌بیند.

**در چیدمان، `min-w-0` را فراموش نکنید.**
آیتم‌های grid و flex به‌طور پیش‌فرض زیر عرض محتوایشان جمع نمی‌شوند. نوار
افقی انتخاب روز بدون `min-w-0` کل صفحه موبایل را ۹۸۱ پیکسل عریض می‌کرد.

## قواعد فاز ۳

**افزودن لندینگ‌پیج جدید = پر کردن یک فرم، نه کدنویسی.**
آدرس `/admin/landing/new` را باز کنید، فرم را پر کنید و تیک «منتشر شود»
بزنید. صفحه، sitemap و لینک‌های داخلی همان لحظه ساخته می‌شوند.

**بلوک‌های تکرارشونده با متن ساده وارد می‌شوند، نه JSON.**
بخش‌ها با `### عنوان` جدا می‌شوند؛ سؤالات و ردیف‌های مقایسه هر خط یک
رکورد با جداکننده `|`. تبدیل در `lib/landing-content.ts` انجام می‌شود.

**پایان خط را همیشه یکسان کنید.**
مرورگر متن textarea را با CRLF می‌فرستد. تابع `splitLines()` این را حل
می‌کند. اگر پارسر جدیدی نوشتید حتماً از همان استفاده کنید — بدون آن،
الگوهایی که به انتهای خط تکیه دارند بی‌صدا شکست می‌خورند و محتوا دور
ریخته می‌شود. این باگ یک بار واقعاً اتفاق افتاد.

**اسلاگ صفحه منتشرشده را عوض نکنید.**
لینک‌های گوگل می‌شکنند. برای بازنشستگی یک صفحه، تیک انتشار را بردارید؛
حذف فقط وقتی که هرگز منتشر نشده باشد.

**مسیرهای ثابت سایت در `RESERVED_SLUGS` هستند.**
اگر مسیر جدیدی به سایت اضافه کردید (مثلاً `/faq`)، اسلاگش را به آن
مجموعه اضافه کنید تا کسی نتواند لندینگی با همان نام بسازد و مسیر واقعی
را پنهان کند.
